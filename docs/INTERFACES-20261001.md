# BOSS 当前接口与采集依据

2026-10-01。以下是本机当前网页的业务观测，不是官方API契约。来源分为实际业务响应、公开脚本路径线索和固定第三方源码；三类证据不互相替代。

## 实际读通的必要通道

| 功能 | 现行路径、方式 | 已确认的业务含义 |
|---|---|---|
| 关键词搜索 | `POST /wapi/zpgeek/search/joblist.json`，表单编码 | city/query/page/pageSize/scene及筛选条件；每页15；四页60次观察、58个唯一ID，跨页会重复 |
| 推荐 | `GET /wapi/zpgeek/pc/recommend/job/list.json` | 每页15；参数另含encryptExpectId、expectInfo、mixExpectType，是求职期望上下文，不能作为关键词样本导入 |
| 主详情 | `GET /wapi/zpgeek/job/detail.json` | securityId/lid来自当前业务上下文；jobInfo.encryptId对应列表encryptJobId，正文在postDescription；同次状态、活跃度和公司信息各有独立字段 |
| 卡片详情变体 | `GET /wapi/zpgeek/job/card.json` | 本机同源读通code=0，返回jobCard、encryptJobId及login等字段；与已选岗位ID匹配，正文519字；字段比主详情少，不当成完整元数据替代品 |
| 登录证据 | `GET /wapi/zpuser/wap/getUserInfo.json` | 本机成功响应code=0，zpData.userId为正整数。采集器只保存authenticated和观察时间，不保存账号ID或token到访问证据 |
| 筛选字典 | `GET /wapi/zpgeek/pc/all/filter/conditions.json` | 官网返回学历、经验、薪资、规模、融资和求职类型枚举；发现并修正旧兼职/实习代码写反 |
| 城市和行业字典 | `/wapi/zpCommon/data/city.json`、cityGroup.json、industry.json等 | 正常页面实际加载；本轮观察了结构，未声称把全部地理/行业子类逐项验收 |
| 独立状态页 | `GET /job_detail/<ID>.html` | 匿名HTML中能读取岗位标题、状态容器和活跃文字；真实结果包括招聘中与职位已关闭，无需把预览正文误标为全文 |

原GET搜索每页30的已有批次仍保留；新增原生方式单独建立批次。实际参数回读用于确认搜索条件，不靠URL计划文本推断已采到预期样本。搜索总数与hasMore是响应字段，不是全国市场覆盖承诺。列表首次观察时间也不是岗位发布日期：本轮读取的原生列表原始字段没有date/time/publish字段。

项目原来的兼职1902、实习1903写反，已改为官网映射。实习查询杭州AI Agent两页30个唯一ID；兼职查询杭州Python一页15个唯一ID。输出字段4/6只是本次样本的实际值，不把请求代码直接套到响应字段上，也不据此宣布所有输出枚举已穷尽。

本科203、1–3年104、应届生102、全职1901此前也已按实际POST核对。列表/正文里的经验和岗位性质仍按原文表达，不能仅凭列表条件推断候选人资格。

## 匿名正文是否能解码成全文

对同一岗位进行了登录和独立匿名两组真实观测。匿名会话是`.browser-interface-anonymous`，没有退出、复制或清理主登录会话。

登录页面可见正文1321字；匿名页面可见410字，节点完整textContent398字。去空白后分别1285/392字，共同前缀384字。取登录全文后半段三个不同片段，在匿名原始HTML和完整DOM中均未找到；匿名预览私用区字体字符数为0。

这一样本没有发现“全文已经下载、只是CSS隐藏”的证据，不能通过展开节点或字体替换还原未收到的后文。该结论仅覆盖此样本和当前响应，不伪称穷尽所有页面变体。采集全文继续使用已登录业务；匿名预览可以保留为来源证据，不能作为本轮完整资格和技能结论。

`anonymous`数值与匿名公司岗位相关，不能拿它判断账号登录。采集器现在同时要求页面没有显示登录入口和服务端正用户ID证据；原生卡片详情还核对页面显示。登录证据最多沿用60秒，超龄后读取一次普通同源登录状态，避免长任务用启动证据确认后来的预览正文。匿名会话的实际拒绝发生在额外详情请求前，增量请求数0。

## 状态与正文独立

独立匿名同源文档读取的三份真实结果：2份招聘中、1份职位已关闭。旧库标关闭的其中一份当前页面显示招聘中，因此旧job_invalid不能当硬事实，状态观察时间必须独立记录。HTTP200、非空状态节点、招聘者刚刚活跃也不能单独说明岗位开放：关闭岗位也可显示刚刚活跃。

现有FETCH_STATUS通过具体容器取值，再核对最终URL、标题与明确状态文案。该对照未写回生产岗位状态，也未改变正文时间；用于校验现有判读链路。

## 国内跳板现状

实际配置为SOCKS5 `127.0.0.1:1080`，初查未监听；SSH别名bohrium-vm实际连接成功，sshd现场允许转发（与旧记忆“只有OCI允许”不同）。已启动限定回环的SSH动态转发，启动PID35420，SOCKS5无认证握手返回0500。没有改远端sshd或系统防火墙。

随后通过同一`.browser-refresh`代理会话打开目标岗位进行单页人工复检：HTTP200、目标ID路径和标题一致、招聘中状态可读，没有验证码或账号凭据。依据此实际BOSS业务响应恢复独立刷新访问，服务刷新3/3通过；审计确认状态写入与批次匹配，正文、正文时间及列表观察时间未变化。此前的SSH握手和匿名直连结果并未被当作恢复依据。

连续12条旧流程实测在第6、第11条收到HTTP200安全页重定向，用户两次仅刷新页面即可恢复，看到的是登录弹窗而非手动验证码；没有明确JSON code=37。该12条最终完成，先前未知观察保留。新流程只对该明确会话页、无验证码或限制提示时普通导航当前岗位一次，整轮最多3次。另一组12条真实代理任务全部通过，2次页面复检、0人工介入，状态与时间分离审计通过；已关闭岗位代理对照也通过。该结果不代表不限量运行，真实验证及限制继续暂停。

用户随后要求休眠收尾：全部任务结束，临时SSH通道停止，刷新因基础设施收尾人为暂停。唤醒后的网络与页面可用性需重新现场核对，当前暂停不作为平台封禁证据。
